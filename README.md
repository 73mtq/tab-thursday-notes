## 这份文档是什么

飞书上的原页面是一个**索引式汇总**：每位分享者只有一行简介加几个外链，没有正文。

本文在逐条访问其个人主页、产品站点、GitHub 仓库与公开报道之后扩写而成。每一章都包含五段结构：

1. **身份与场景** — 这个人是谁，在什么位置上做这件事
2. **他讲了什么** — 分享内容的客观还原
3. **关键点拆解** — 5–7 条，说明「为什么这样设计」「难点在哪里」
4. **可迁移的方法** — 可以拿去用的具体动作
5. **边界与提醒** — 这个方案的局限、代价、失效条件

### 第五部分 · 横向总结

18 个案例收敛出的 5 条判断：

1. **最好的资源，往往是你已经拥有的那个** —— 以陈、Edward、海涛、草原张都在做同一件事：先盘活存量，再考虑新增
2. **「可编辑」比「能生成」难，也比「能生成」值钱** —— 用户不介意第一版难看，介意的是改不动
3. **合规与授权，正在成为技术方案的一部分** —— 绕过去的方案更快，但更短命
4. **小团队的护城河是「细节密度」，不是功能数量** —— 功能会被复制，细节不会
5. **真正的瓶颈已经从「执行」转移到「判断」** —— 生产成本塌陷后，稀缺的是品味与验证

## 怎么读

- **只有十分钟**：直接跳到第五部分，那里把 18 个案例收敛成 5 条判断。
- **对某个方向有兴趣**：每章可独立阅读，不必按顺序。
- **想找方法**：每章末尾的「可迁移的方法」是压缩过的行动清单。
- **准备做产品**：先看「边界与提醒」，那里写的是别人踩过的坑。

## 事实边界

这份文档对「可信」有一条硬线：**不把推断写成事实。**

- **厂商自测数据**已单独标注。Ego lite 的 398s/587s/605s/615s、1.64/2.43/2.66 美元，对照组配置未公开，只能作为方向性参考。
- **未完成验证的方案**已注明。iPhone Use Pro 只在作者本机（Apple Silicon + macOS 27.0.1 + iPhone 16 Pro）实测通过，仓库原文写着「不要把本机验证当成其他机器验证」。
- **信息不足的四位**（14 Wentao / 16 冯中 / 17 天天 / 18 imxiaorong）公开材料仅有一行主题描述，对应章节改为「以主题为锚点 + 行业通行框架」的方法论推演，凡属推断均在文中标明。
- 即刻、小红书短链在未登录状态下无法抓取，部分分享者的完整内容可能未被覆盖。

## 静态站点

[在线阅读](https://73mtq.github.io/tab-thursday-notes/) 由仓库 `docs/` 目录通过 GitHub Pages 发布（分支 `main` / 目录 `/docs`）。站点提供：

- **首页**：两期入口、第二期按主题跳转，以及 39 位分享者的**主页 + 项目链接索引**（每张卡片可跳本站精读章节，也可直达外部站点）；
- **章节内**：每章顶部列出该分享者的主页、介绍的项目、源码、幻灯片、样片等链接，取自官方汇总页；官方没给的会如实标注；
- **文章页**：粘性侧栏目录（可按分享者姓名筛选、`Ctrl/⌘ + K` 定位）、章节锚点、阅读进度条、返回顶部；
- **移动端**：正文 16–16.5px / 行高 1.85，右下角「目录」悬浮按钮打开带遮罩的抽屉，触摸目标 ≥44px，表格可左右滑动并有提示，尊重 iOS 安全区；支持 `prefers-color-scheme: dark` 与 `prefers-reduced-motion`；
- **跳转**：全部外部链接在新标签页打开，两期附录中的裸域名也已转成可点击链接；地址误带 `**` 等字符时 404 页会自动跳回首页。

本地重建：

```powershell
python -m pip install markdown
python .\build_site.py
```

`build_site.py` 读取仓库根目录的两份 Markdown 与 `links.json`，生成 `docs/` 下的 HTML、CSS、JS、`404.html` 与 `.nojekyll`。`links.json` 由 `refresh_links.py` 从官方汇总页抓取并按人结构化（主页 / 项目链接），已随仓库提交，因此构建过程完全离线；官方发布新一期或链接有变动时才需要重跑：

```powershell
python .\refresh_links.py
python .\build_site.py
```

新增期数时还需修改 `build_site.py` 顶部的 `ISSUES` 与 `refresh_links.py` 的 `PAGES` 配置。改动 Markdown 后先重建再提交，站点会自动更新。
